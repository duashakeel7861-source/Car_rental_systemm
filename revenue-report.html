Date Overlap Check & Concurrency Control

Project 7 Specification

SQL Trigger / Transaction Isolation: 

CREATE TRIGGER check_booking_overlap
BEFORE INSERT ON Bookings
FOR EACH ROW
BEGIN
  IF EXISTS (
    SELECT 1 FROM Bookings
    WHERE car_id = NEW.car_id
      AND status != 'Cancelled'
      AND NEW.start_date <= end_date
      AND NEW.end_date >= start_date
  ) THEN
    SIGNAL SQLSTATE '45000'
    SET MESSAGE_TEXT = 'Date Overlap: Car already booked!';
  END IF;
END;

What happens when two users book at the same second?

When two concurrent requests arrive simultaneously for the exact same vehicle and dates:

  • Pessimistic Locking: Using SELECT * FROM Cars WHERE car_id = X FOR UPDATE locks the row inside a transaction. The second user waits until the first transaction commits.
  • Serializable Isolation: Setting transaction isolation to SERIALIZABLE detects read/write anomalies and aborts the conflicting transaction with a retry directive.
  • Distributed Locks: In microservices, a Redis lock (SET car_lock:123 NX EX 10) ensures atomic serialization across distributed nodes.
